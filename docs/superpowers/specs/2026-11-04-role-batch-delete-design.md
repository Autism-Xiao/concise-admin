# 角色管理批量删除设计

## 目标

在角色管理列表中增加复选框和批量删除能力，复用通知公告列表已有的交互模式，不改变单个删除、编辑和分配权限功能。

## 方案

后端当前仅提供 `DELETE /api/v1/roles/:id`，前端对选中角色并发调用现有单条删除接口，通过 `Promise.allSettled` 分别统计成功与失败。相比串行删除，该方式等待时间更短；相比新增批量接口，不需要修改后端。

## 页面交互

- 表格首列增加行复选框，表头复选框用于全选或取消全选当前页，并支持半选状态。
- 使用角色 `id` 作为行唯一标识，跨页保留选择。
- 勾选角色后，在表格工具栏显示“批量删除（数量）”按钮；未勾选时不显示。
- 点击批量删除后打开确认弹窗，明确展示即将删除的角色数量。
- 删除执行期间显示处理中状态并禁止重复提交。
- 完成后分别提示成功和失败数量，清空选择并重新加载角色列表。
- 单个删除继续使用现有确认弹窗和接口。

## 代码范围

只修改 `src/features/system/role/index.tsx`：

- 在列定义开头加入选择列。
- 从 `useDataTable` 取得 `rowSelection`、`setRowSelection`，并配置 `getRowId`。
- 增加批量删除确认状态、执行状态和处理函数。
- 在工具栏与弹窗区域加入批量删除 UI。

复用现有 `ConfirmDeleteDialog`、`Button` 和 `deleteRole`，不新增组件或 API。

## 异常处理

每个删除请求独立结算。部分失败时仍保留成功结果，成功和失败数量分别通过 toast 展示，最后统一刷新列表。刷新失败沿用页面现有错误状态和重试入口。

## 验证

- TypeScript 无类型错误。
- ESLint 检查通过。
- 浏览器验证本页全选、半选、单行选择、跨页保留、取消选择和确认弹窗。
- 使用页面内模拟请求验证全部成功、部分失败和重复提交防护，不删除真实角色数据。
